# v3.42.4

## 原生 WS 预连接

- 增加会话备用 WS 预连接，不依赖补号或请求兼容插件。真实新链完成选号后，按当前调度策略只读评估一个后备账号，提前完成握手，不发送生成请求、不占业务并发租约、不修改会话亲和
- 后备账号必须凭据就绪、套餐已知、额度确认可用，并符合本次模型与账号授权范围。未知或耗尽额度不预建，大号池不会按账号数量自动建满连接
- 切号请求通过正常选号与准入后，原子领取匹配的备用连接。按 Client Key、凭据版本、会话、代理及握手身份隔离，不跨会话复用已发送业务内容的连接
- 后台握手支持空正文 403、临时网络错误、429 和部分 5xx 的有界重试，遵守 Retry-After 并增加退避与随机错峰。明确权限拒绝不盲目重试，后台失败不直接停用账号或新增模型冷却

## 配置与资源

- 「设置 → 二开配置」增加会话备用预连接开关，以及实例/单账号容量、后台握手并发与速率、保留时间、重试次数和失败暂停时间
- 配置持久化到运行目录 fork-settings.json，保存后生效。关闭或缩小储备由维护任务回收未领取连接，不中断已领取的业务流
- 后台只使用代理空余物理容量，真实请求优先回收未使用储备。客户端断开、账号驱逐、连接超龄及服务关闭时统一取消和回收
- 日志增加准备成功、领取命中、握手失败和回收事件，不记录凭据或历史正文

## 升级事项

- 本功能默认关闭，升级不会自动启用，也不会覆盖现有二开设置。从 v3.42.3 升级无新增数据库迁移，仍建议备份数据库、配置和运行目录
- 当前为已知会话的备用连接，不是未知会话通用空连接池。账号刚导入不会独立触发预建，后续真实新链请求才重新评估候选
- 原生续接仍遵守原账号、原连接和客户端完整重放规则。API Key 上游、隐私/出站中间件、Guardian、固定账号及严格跟随的后代不主动准备备用账号
- 两个真实账号的短请求验证已确认切号命中备用 WS；尚未验证 100+ 并发压测或 403 降幅，预连接不能保证消除上游权限拒绝
- 镜像地址保持 ghcr.io/lsmallice/codex-proxy-rs，更新后同步固定 Compose 标签，避免容器重建回退。发布不自动升级现有运行实例
