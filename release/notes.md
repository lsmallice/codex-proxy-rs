# v3.43.6

## 新增功能

- 新老账号并发交接：支持所有导入入口的新订阅账号自动配对，也可手动指定新老账号并取消交接
- 渐进分流：默认每 5 秒检查，新号稳定运行至少 30 秒且有 3 次成功请求后，将老号并发上限降低 30，最低保留 50 继续消耗余量
- 交接记录：进行中与历史记录分别分页，默认每页 20 条，历史显示完成时间、最终并发及结束原因
- 账号列表刷新：新增工具栏刷新按钮，保留当前筛选、排序和页码

## 优化改进

- 失败回退：新号限流或账号异常时暂停推进并复核恢复上一档，保留真实冷却，不因短暂 429 停用老号
- 并发约束：临时交接上限与现有账号配置独立，实时准入原子复核，不中断在途请求或绕过权限、模型和续接边界
- 重启恢复：交接状态保存在 Redis，观测中断后重新累计稳定窗口，无业务流量时不继续降档

## 升级须知

- 无新增数据库迁移，升级前仍需备份数据库、运行配置和 Redis 持久卷
- 自动交接默认关闭，在账号管理中开启；只识别开启后新建、同组且已就绪的 OpenAI OAuth 订阅账号，已有账号更新及 API Key 账号不自动参与
- 新号保持原并发配置，初始承接目标不是硬上限；总负载突增或老号提前失效时，仍可能超过目标承接量
- 老号最低保留并发不延长实际有效期或绕过额度限制，停用、删除、耗尽及明确失效后结束交接
- 历史保留最近 7 天、最多 10000 条，升级前没有索引的已结束记录不补造；Redis 数据丢失后自动策略回到关闭
- 本次仅发布 CPR 主程序，不包含独立补号插件安装包；插件自适应并发开启时须使用支持原生交接避让的插件版本
- 镜像为 ghcr.io/lsmallice/codex-proxy-rs:3.43.6，发布不自动升级运行实例
