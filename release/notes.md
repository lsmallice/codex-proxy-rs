# v3.51.3

## 问题修复

- 会话粘性：健康且有容量的已绑定会话不再为分层均衡每轮换号，容量交接成功后保留新绑定，避免原号恢复空位后反复切回
- 发送保护：已命中会话亲和时在原账号有界等待令牌，保留瞬时限流，不为避开等待反复换号
- 消耗优先：无活动交接时老号优先填补保留并发目标，达到目标后新增会话按负载均衡，修复无限并发老号独占流量
- 交接角色：自动组中完成保护且达到消耗条件的承接账号，在存在更新且健康的承接后继时转入老号层，保留已减载上限并重新观察
- 容量展示：交接承接上限不再错误显示为新账号并发保护，真实保护记录与交接上限分别投影
- Lite 兼容：Guardian 自动审批生成请求不再跳过已开启的 Lite 补正，HTTP 与 WS 均显式发送 parallel_tool_calls=false，保留原存储意图与审批正文

## 升级须知

- 相对 v3.51.2 无新增数据库迁移或配置字段，已有交接参数、保护进度和幂等回执保留
- 已绑定会话优先稳定，不保证实时并发完全均分；只有一个可用账号时不能凭调度产生额外承接容量，实际并发与发送保护仍按配置执行
- 自动组角色转换不重置保护、不恢复已减载负载，也不立即使用旧预算卸载；手动指定组的角色保持不变
- Lite 请求兼容仍由现有 lite_context 开关控制，关闭或非 Lite 请求沿用原行为
- 补号扫描时间修复由独立补号插件 0.2.8 提供，不随 CPR 镜像安装
- 保留已批准的 picomatch GHSA-fc5q-39xc-vjpf 构建依赖单项审计例外，其他安全检查不变
- 本次仅发布 CPR，不升级或重启线上 CPR 实例
