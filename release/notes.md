# v3.42.3

## 发行修正

- 修复二开设置动态翻译键无法通过完整前端检查的问题，删除废弃文案，不关闭检查规则
- 修复大量插件调用同时取消时，250ms 确认窗口可能误杀会话的问题。确认宽限调整为 2 秒，业务权限与回调仍立即撤销，在途名额收到确认后释放，无响应插件仍按上限终止
- v3.42.1 与 v3.42.2 未完成发行，本版包含以下全部二开能力与官方更新

## 二开请求恢复

- 基于官方 v3.42.0，保留同账号、同凭据、同代理的空正文 WS 握手 403 有界恢复；协议允许时沿用原生 HTTP/SSE 降级，不放宽普通权限拒绝
- 增加无实质输出时的 WS 断流补发，额外次数可设 0–5，检查窗口和前导总量有界；已输出内容、工具或未知事件时不重放
- 旧连接不可用时，可依据宿主保存的完整历史摘要恢复一次；增量历史或归属不明时仍返回原续接错误
- 增加 OpenAI OAuth 上游 WS 的失效密文定点恢复与摘要记忆。普通消息保留明文和 phase，推理项保留非空摘要，纯密文和压缩项不直接删除。迟到错误仍返回，下一轮同范围请求可提前清理
- 密文摘要在内存中保留 30 分钟，按调用方、会话、账号、凭据版本、模型、实际安装身份和代理隔离。默认最多 65,536 个范围、每范围 512 条，按需分配，重启清空

## 原生兼容与热更新

- Lite 上下文、OAuth store=false、JSON 模式指令、最低 16 Token 和工具结构补正可分别启用，不依赖旧请求兼容插件，也不映射推理档位
- 工具仅修复明确的嵌套 function 格式。非法名称或冲突定义返回明确 400，不静默删除工具或历史
- 模型不支持冷却时间可配置为 0，表示不新增且忽略已有模型级冷却；账号级限流、额度与错误保护保持生效
- 设置页增加独立「二开配置」。请求兼容、模型冷却和 WS 恢复策略保存后对新请求及 WS 下一轮生效，在途请求与重试保持原快照
- 插件容量、HTTP 路径过滤及密文缓存容量仍需重启，页面区分当前生效值与待重启值。配置保存在运行目录 fork-settings.json，写盘失败不发布

## 官方 3.42.0 合并

- Key 与账号排队超时分开配置，账号队满或超时时可选择尝试其他立即可用账号；固定账号与原生续接不因该设置换号
- 合并大号池调度优化、会话与缓存亲和改进、账号「自动使用点数」开关以及按 Key 与账号派生的安装身份
- 合并 Codex OAuth 默认采样参数与旧 token 上限兼容，旧字段转换后仍遵守已启用的最低输出预算
- 更新检查使用固定发布索引和精确 tag，不遍历 Release 列表。二开与官方来源预检复用索引并保持只读，不执行一键换版

## 升级事项

- 镜像与更新源保持为 ghcr.io/lsmallice/codex-proxy-rs 和 lsmallice/codex-proxy-rs，不切换到官方原版
- 新增请求兼容与恢复开关默认关闭。部署后按需要启用，再停用旧「Codex 请求兼容」插件，避免重复改写和补发；不自动迁移插件配置
- 清理密文是有损恢复，补发可能增加计算或计费。密文缓存全部打满时仅摘要数据约 1 GiB，另有索引开销
- 通过管理 API 或插件 SDK 更新运行设置时，用 keyQueueTimeoutSeconds、accountQueueTimeoutSeconds 和 switchAccountOnQueueFailure 替换 concurrencyWaitTimeoutSeconds。旧排队时长分别继承，换号默认关闭
- 已配置的 Key 安装 ID 转为 installationSeed 后，安装身份与关联缓存标识会变化，已有精确 WS 续写可能需要客户端重新提交完整上下文
- 从 v3.41.1/v3.41.2 正式迁移集合升级只新增 0039。执行过中间版 main 的 0039_queue_timeouts.sql、0040 或 0041 的数据库不能直接覆盖升级或修改 checksum，须先在独立库验证迁移方案
- 升级前备份数据库、配置和插件数据，保留运行目录挂载。首次安装本版需重启，后续请求策略修改可热生效；网页更新后仍须同步 Compose 镜像标签，避免重建时回退
